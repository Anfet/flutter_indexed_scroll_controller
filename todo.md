# TODO: вертикальная прокрутка по индексу

Цель выпуска: надёжный вертикальный `ListView.builder` сверху вниз с элементами разной высоты. Фактические высоты по индексам остаются в словаре; неизвестные элементы измеряются последовательным проходом. Индексы `watch()` обозначают физические позиции строк `ListView.builder` сверху вниз, от 0 без пропусков; решение зафиксировано в ISC-27. Горизонтальный режим, обратный список и новый компонент списка не блокируют этот выпуск. Обоснование и DoD прежних блоков — в [eng-review.md](eng-review.md); новые расхождения и их критерии проверки перечислены в задачах ISC-22–ISC-39. После завершённого ISC-20 выпускной контроль требуется повторить по ISC-39.

Статусы: `todo`, `in progress`, `ready for review`, `blocked`, `arch required`, `done`. Таблица отсортирована по порядку выполнения атомарных операций. Идентификаторы сохранены после изменения приоритета, поэтому идут не строго по номеру. «Luna»/«Terra»/«Sol» — подходящая модель исполнения, а не отметка о состоявшемся делегировании. Завершённые (`done`) задачи в этой таблице не хранятся — их строки перенесены в [eng-review.md](eng-review.md#архив-завершённых-задач-перенесено-из-todomd).

## Правила выполнения

- Статусы задачи: `todo`, `in progress`, `ready for review`, `blocked`, `arch required`, `done`.
- Исполнитель, завершив задачу, ставит `ready for review`, а не `done`.
- Ревьюер (Terra) переводит `ready for review` в `done` (готово) или обратно в `todo` с конкретными пометками (мелкий дефект реализации/теста — доработка на том же уровне). Ревьюер не перезапускает исполнителей сам; решение о перезапуске остаётся за инженером.
- Если ревью обнаруживает не точечный дефект, а архитектурную проблему (требуется пересмотр дизайна/контракта, а не локальный фикс), ревьюер переводит задачу в `arch required` вместо `todo`, с описанием сути конфликта. Такая задача не возвращается исполнителю Luna/Terra до решения на уровне Tier 1 (Opus/Sol) или явного решения инженера.
- Закрывать задачу только с указанным тестом или другим проверяемым артефактом. В отчёте указывать фактическую команду и результат.
- Отсутствие прогресса определяется после завершённых шагов; общий лимит кадров служит страховкой теста, а не правилом поиска.
- Для первого выпуска оставить словарь высот. Индексы `watch()` должны совпадать с физическими позициями строк `ListView.builder` по решению ISC-27; одной непрерывности недостаточно. Обнаруженный пробел должен давать `StateError`, а не приватный `_TypeError`. Префиксные суммы не нужны без измеренного узкого места.
- Полный сброс применяется при реальном изменении состава, порядка или скрытой высоты строк, а не при каждом `build`. Обычная выгрузка строки не удаляет измеренную высоту.
- Для ручного `watch()` вызывающий код обязан вызвать инвалидацию после изменения данных. Пока новый компонент не выпущен, это часть публичного контракта ручного API.
- Не затрагивать горизонтальный/обратный скролл и имеющееся изменение `example/pubspec.lock` без необходимости задачи.
